AUTOMATION / CONNECTORS

Connect Latch to your automation

Use the local REST API from scripts or an automation running inside this VM. Latch returns a scan ID first; poll it for the per-URL reports.

LOCAL API · MCP NOT INSTALLED

1 · Start a scan

Run this in Git Bash or a terminal on the same VM. Replace the example URL with the URL you want analyzed.

curl -s -X POST http://127.0.0.1:8787/api/scans \\
  -H 'Content-Type: application/json' \\
  -d '{"urls":["https://example.com/"]}'
  1. Copy the returned scan.id.
  2. Poll the scan endpoint until scan.status is complete.
  3. Read each URL's result from scan.items[].

2 · Get progress and reports

Use the scan ID returned by the first request. In n8n, make one HTTP Request node for POST, then loop this GET request while the scan is running.

curl -s http://127.0.0.1:8787/api/scans/SCAN_ID
GET/api/configprovider and browser availability
GET/api/scansrecent scans
POST/api/scansstart scan with {"urls":[...]}
GET/api/scans/{id}progress and full results
Access boundary: the API listens on 127.0.0.1 only and has no API token yet. Keep the automation on this VM; hosted n8n/Zapier or another computer cannot reach this address. Do not expose the port publicly.
About MCP: Latch does not currently include an MCP server. MCP is an adapter an AI agent can use; the same scan API can support one later. For now, use REST / HTTP Request. Add authentication before enabling remote access or an MCP endpoint.
